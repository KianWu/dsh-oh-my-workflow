# wf-engineering — 通用工程基线

这些规则跨项目成立；项目自己的命名、目录、格式和平台红线优先于本基线。

## 开工前

1. **明确边界**：用一两句话写清改什么、不改什么、验收标准与默认假设。范围不清时先问或先读，不猜。
2. **复用优先**：先找现有函数、组件、配置和模式。创建第二份实现前，说明既有实现为何不可用。
3. **读后改**：读取要改的代码，以及行为变化会影响的调用方；只读需要的范围。

## 实现中

4. **解根因**：不用兜底、双路径、静默吞错或复制实现掩盖问题。临时兼容必须写明退出条件。
5. **最小 diff**：不整文件重写、不顺手重构、不添加没有调用方的抽象。删除优先于新增。
6. **小步验证**：每完成一个可验证的改动，运行一条真实命令；不要攒到最后才跑。
7. **公开接口**：改变公开接口时兼容旧调用，或提供迁移说明和版本边界。

## 收尾

8. **清理孤儿**：只清理本次改动造成的临时脚本、日志、备份和未使用文件；无关的既有问题只记录，不顺手修。
9. **同步文档**：结构、命令和行为变化同步长期文档；不复制规范全文，只维护入口与事实。
10. **证据汇报**：汇报分三段——改了什么、如何验证（命令与结果）、还剩什么（未验证范围/后续项）。不把推测写成结果。

## 协作与委派

- 可拆成多个独立子任务，或需要宽搜索 / 批量阅读 / 独立评审时，拆给 `subagent` / `subagent_fork` 并行处理；主线只保留结论、证据与集成。
- 子代理用新上下文、只回传结论与证据（命令 / 退出码 / 文件:行），不把原始大段输出带回主线。
- 简单任务不要为委派而委派。

## 验证分级

- **强证据**：测试、构建、类型检查、目标程序运行，真实完成且退出码为 0。
- **写入证据**：读回文件、diff、stat；只能证明文件变化，不能证明行为正确。
- **无证据**：工具返回成功、模型声明、计划、推测。
- 无法验证时，明确写出「未验证范围 + 原因」，不要用「应该没问题」代替。

## 失败止损

同一修法连续失败两次：停止尝试第三个变体。列出这些尝试共同的前提，直接用最小实验验证该前提，再换路径（st-unstick）。

## 完成检查单

- [ ] 改动范围与开工时说的一致，没有顺手扩大。
- [ ] 每条完成声明都有对应的真实命令结果。
- [ ] 没有留下临时文件、调试输出或未使用代码。
- [ ] 受影响的长期文档已同步。
- [ ] 汇报区分事实、推断与未完成项。
