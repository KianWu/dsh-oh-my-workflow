# wf-route — 三档路由与长任务分支

## 目标

用最小够用的流程完成任务，而不是让所有任务都走重型流水线。路由在读取必要信息后做一次，任务范围变化时重新判断。

## 三档

| 档位 | 触发条件 | 默认行为 | 验证要求 |
|---|---|---|---|
| 快速档 | 目标明确、改动小、风险低，通常单文件 | 读取必要代码后直接修改并验证 | 至少一条能证明改动的真实命令；纯文档改动可说明豁免 |
| 标准档 | 多文件，或存在可见行为变化 | 先给简短计划（3–6 步）→ 实现 → 验证 → 自查 | 测试、构建、类型检查或目标程序运行 |
| 深入档 | 需求含糊、高风险、涉及结构/接口/数据流变化 | 澄清 → 建模或规格 → 用户确认 → 拆分并行委派 → 实现 → 验证 → 评审 | 按规格验收，保留规格/计划/ADR |

判定倾向：

- 不确定时选**标准档**；只有真正含糊或高风险才升**深入档**。
- 只有一个文件但改动公共 API、数据迁移、权限或安全边界，按**深入档**。
- 只改文案、注释、README 且无行为变化，可按**快速档**。
- 任务开始时用一句话说明档位和理由，不要长篇解释。

## 多 agent 协作

复杂、深入档或长任务，默认不是单线程扛到底。满足任一条就拆分并委派：

- 有 2 个以上边界清晰、可独立推进的子任务（不同模块 / 文件集 / 调研问题）；
- 需要宽搜索、批量阅读、日志或数据普查，原始输出很大；
- 需要独立评审、第二意见，或一个不含本对话历史的干净上下文。

分工与选型：

- `subagent`：全新上下文，自包含任务（研究、批量检索、独立实现、评审），可同时起多个并行。
- `subagent_fork`：继承当前对话，用于接续已有结论的后续分析或评审。
- `workflow`：按脚本对大量文件 / 条目扇出（审计、迁移、批量验证）。
- `list_agents` / `send_message`：查看、续接已存在的子代理。

主线保留目标、关键决策、跨子任务集成与最终验收；子代理只回传结论、证据（命令 / 退出码 / 文件:行）和文件指针，不回传大段原始输出。简单任务不要硬拆。

## 长任务分支

长任务是正交分支，可与标准档或深入档组合，触发条件：

- 预计跨多个阶段或多个会话；
- 需要并行调查、批量阅读或独立评审；
- 需要跨会话交接；
- 有多个待定的设计决策。

启用后使用：

- `st-ledger`：每个决定记一行，每步开始前读回。
- `st-context-reset`：维护 `.agent/workflow/PROGRESS.md`，新会话只读它继续。
- `to-tickets` / `wayfinder`：拆成带阻塞边的工单或决策地图。
- `handoff`：离开前压缩成交接文档。

快速档不创建计划、规格、工单、进度或交接文档。

## 路由输出

第一次回复只需要一行：

```text
路由：标准档（多文件 + 可见行为变化）｜长任务：否
```

若用户没有要求流程说明，不要重复解释三档定义，直接开始工作。

## 反模式

- 给一个小修小补写完整规格和工单。
- 需求含糊却直接改代码。
- 深入档未经用户确认就开始大规模实现。
- 快速档顺手重构、扩大范围。
- 复杂/长任务全自己扛，上下文越滚越大、反复重读。
- 长任务只靠聊天记忆，不写 PROGRESS/ledger。
